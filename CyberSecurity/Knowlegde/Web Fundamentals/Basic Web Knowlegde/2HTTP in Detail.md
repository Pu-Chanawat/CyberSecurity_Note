#### What is HTTP(S) ?
HTTP คืออะไร ?
- HTTP ย่อมาจาก HyperText Transfer Protocol
- HTTP คือ Protocol พื้นฐานที่ใช้ในการรับส่งข้อมูล Website (Ex. HTML / Media) เปรียบเสมือนภาษากลางที่ Browser ใช้คุยกับ Server

HTTPS คืออะะไร
- HTTPS ย่อเหมือน HTTP แค่ S คือคำว่า Secure 
- HTTPS คือ  HTTP + Encryption (การเข้ารหัสข้อมูล)
- จุดเด่นของ HTTPS :
	- ป้องกันการดัดฟัง
	- ป้องกันข้อมูลจะถูกแก้ไขระหว่างทาง
	- ใช้ยืนยันตัวตนได้

#### Requests And Responses
URL คืออะไร ?
URL หรือ Uniform Resource Locator
คือ คำสั่งที่บอกวิธีการเข้าถึงทรัพยากร (Rosource) บน internet เช่น การเข้าหน้า Web 
![[Pasted image 20260409193201.png]]
โดยมีองค์ประกอบ
- Scheme : ระบุ Protocol ที่ใช้ เช่น HTTP , HTTPS , FTP
- User : บริการบางอย่างต้องใช้การระบุตัวตน คุณสามารถใส่ Username และ Password ลงใน URL ได้
- Host/Domain : Domain Name หรือ IP Address ของ Server ที่ต้องการเข้าถึง
- Port : Portที่จะเชื่อมต่อ เช่น โดยปกติ HTTP - 80 , HTTPS - 443
- Path : ชื่อไฟล์หรือตำแหน่งทรัพยากรที่ต้องการ
- Query String : ข้อมูลเพิ่มเติมที่ส่งไปพร้อมกับ Path เช่น `/blog?id=1` เพื่อต้องการบทความไอดีที่ 1
- Fragment : คือการอ้างอิงตำแหน่งภายในหน้าเพจนั้นๆ มักใช้กับเนื้อหายาวๆ เพื่อเลื่อนไปยังส่วนที่กำหนดทันทีที่เข้าหน้าเว็บ

#### HTTP Methods
HTTP Methods เปรียบเสมือน "คำกริยา" ที่บอก Server ว่าเราต้องการทำอะไรกับข้อมูล (คล้ายกับหลักการ CRUD ในฐานข้อมูล) 
โดยมีดังนี้
- GET (Read) : ดึงข้อมูลมาดูเฉยๆ
- POST (Create) : ส่งข้อมูลใหม่ไปให้ Server
- PUT (Update) : แก้ไขข้อมูลเดิมที่มีอยู่
- DELETE (Delete) : ลบข้อมูลทิ้ง
ในมุมมอง Cyber การที่ Server เปิดให้ใช้งาน PUT หรือ DELETE โดยไม่มีการควบคุมสิทธิ์นั้นอันตรายมาก อาจจะเป็นช่องโหว่นึงก็ได้
#### HTTP Status Codes
ในบทเรียนก่อนหน้านี้ คุณได้เรียนรู้ว่าเมื่อ HTTP Server มีการตอบกลับ บรรทัดแรกจะประกอบไปด้วย Status Code เสมอ เพื่อแจ้งให้ฝั่งผู้ใช้ (Client) ทราบถึงผลลัพธ์ของคำขอ และวิธีจัดการต่อ 
โดยรหัสเหล่านี้แบ่งออกเป็น 5 กลุ่มหลัก
- 100-199 (Information Response) : แจ้งว่าได้รับคำขอส่วนแรกแล้ว และ ให้ส่ส่วนที่เหลือมาต่อได้เลย (ปัจจุบันจะไม่ค่อยเจอแล้ว)
- 200-299(Success) : แจ้งว่าคำขอสำเร็จเรียบร้อยแล้ว
- 300-399 (Redirection) : ใช้เพื่อส่งผู้ใช้ไปยังทรัพยากรอื่น (หน้าเพจอื่นหรือ Website อื่น)
- 400-499 (Client Errors) : แจ้งว่าเกิดข้อผิดพลาดจากฝั่งผู้ใช้เอง
- 500-599 (Server Errors) : เกิดข้อผิดพลาดทางฝั่ง Server

รหัสสถานะที่พบบ่อย
- 200 - OK : คำขอเสร็จสมบูรณ์
- 201 - Created : สร้างทรัพยากรใหม่สำเร็จ เช่น New User Account
- 301 - Moved Permanently : ย้ายหน้า page ถาวร (บอก Search Engine ให้ไปเก็บข้อมูลที่ที่อยู่ใหม่แทน)
- 302 - Found : ย้ายหน้าเพจชั่วคราว 
- 400 - Bad Request : คำขอผิดพลาดหรือไม่ครบถ้วน 
- 401 - Not Authorised : ไม่ได้รับอนุญาตให้เข้าถึงจนกว่าจะมีการเข้าสู่ระบบ (Login)
- 403 - Forbidden
- 404 - Page Not Found
- 405 - Method Not Allowed
- 500 - Internal Service Error
- 503 - Service Unavailable 
#### Headers
คือ ข้อมูลเสริมที่เราส่งไปกับคำขอใช้งาน Website แม้ว่าตามกฎเราไม่จำเป็นต้องส่งไป แต่ในความจริง ถ้าไม่มีข้อมูลพวกนี้ มันก็จะแสดงผลหน้าเว็บไซต์ให้เราได้ยากและไม่ดีเท่าที่ควรจึงควรส่งไปเท่าที่จำเป็น

**Request Headers** (ข้อมูลที่เราส่งให้ Server)
- Host : คือการบอกว่า"เราจะเข้าเว็บไหน" เพื่อเป็นความชัดเจนว่าเราต้องการเข้าหน้าไหนนั่นเอง
- User-Agent  : คือบอก Browser ที่เราใช้งาน เพื่อให้เว็บส่งข้อมูลมาแสดงได้เหมาะสมกับ Browser ที่เราใช้งาน
- Content-Length : คือความยาวของข้อมูลที่เราส่งไป เช่น ตอนกรอกข้อมูลอะไรสักอย่าง เพื่อใช้ในการรตรวจสอบว่าข้อมูลที่เราส่งไปครบถ้วนรึป่าว
- Accept-Encoding : คือการบอกว่า  server ว่า ถ้าส่งข้อมูลกลับมา ช่วยบีบอัดด้วยวิธีนี้นะ เพราะเว็บไซต์นี้รองรับการบีบอัดแบบนี้
- Cookie : คือข้อมูลที่ส่งไปให้ Server เพื่อให้มันจำว่าเราคือใคร

**Response Headers** (ข้อมูลที่ Server ตอบกลับ)
- Set-Cookie : เป็นข้อมูลที่ Server ส่งไปให้ Browser จดจำ เมื่อครั้งหน้าที่เราเข้าเว็บมาอีกรอบ ข้อมูลนี้จะส่งกลับไปทางฝั่ง Server เอง
- Cache-Control : บอก Browser ว่าข้อมูลนี้ให้เก็บไว้นานเท่าไหร่ ก่อนที่จะต้องไปขอข้อมูลใหม่จาก Server
- Content-Type : บอกว่าข้อมูลที่ส่งกลับมาคืออะไรบ้าง เช่น ถ้าเป็นหน้าเว็บก็เป็น HTML Coding ไรงี้
- Content-Encoding : คือการบอกวิธีที่ Server บีบอัดไฟล์นี้มา เพื่อให้ Browser แตกไฟล์ออกมาได้

#### Cookies
Cookies คืออะไร ?
	คือข้อมูลที่ถูกเก็บไว้ในเครื่องคอมเรา โดยมันจะบันทึกก็ต่อเมื่อ Server มีการส่ง Set-Cookies มาบอก Browser เรา
	หลังจากนั้น ทุกครั้งที่เราเปิดใช้งาน Website เดิมอีกครั้ง Browser จะทำการส่ง Cookies นี้กลับไปให้ Server ครับ
 
ทำไมต้องมี Cookies ?
	ปกติระบบ internet มันจำอะไรไม่ได้เลย มันไม่รู้ว่าเราทำอะไรบ้าง Cookies เลยเข้ามาทำหน้าที่เป็นตัวขยายจำว่า "เราคือใคร เคยทำอะไรไปบ้าง"

การใช้งาน Cookies ?
- ใช้ "ยืนยันตัวตน" โดยไม่ใช่เป็นรหัสผ่านตรงๆ แต่จะเป็นรหัสลับเรียกว่า Token ซึ่งเดาได้ยาก
