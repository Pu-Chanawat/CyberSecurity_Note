#### What are Packets and Frames
เปรียเทียบกับการส่งจดหมาย
Packet คือ ตัวกระดาษในซองจดหมาย
Frames คือ ตัวซองจดหมาย

- Packet : คือชิ้นส่วนข้อมูลใน Layer 3 - Network Layer ซึ่งข้างในจะประกอบด้วย IP address และ Payload(ตัวเนื้อหาข้อมูล)
- Frame : จะถูกใช้ใน Layer 4 - Data Link Layer  ซึ่งหน้าที่คือ ทำการห่อหุ้ม Packet (Encapsulate) และเติมข้อมูลเพิ่มลงไปคือ MAC address

IP ของตัว Packet จะมีส่วนประกอบที่เรียกว่า Headers ซึ่งมีข้อมูลดังนี้
- Time To Live - เป็นตัวกำหนดอายุของ Packet
- Checksum - ใช้ตรวจสอบความถูกต้องของข้อมูลใน Protocol อย่าง TCP/IP
- Source address - IP address ของเครื่องต้นทาง
- Destination Address - IP address  ของเครื่องปลายทาง
#### TCP/IP
TCP/IP เป็นโทเดลที่ย่อมาจาก OSI Model อีกรอบให้เหลือเพียง 4 Layer คือ
1. Application 
2. Transport
3. Internet
4. Network Interface

คุณสมบัติเด่งของ TCP
- Connection-based : ต้องสร้างการเชื่อมต่อก่อนส่งข้อมูลเสมอ
- Reliability : รับประกันว่าข้อมูลจะส่งถึงปลายทางอย่าง ถูกต้อง และ ครบถ้วน
- Encapsulation : การห่อหุ้มข้อมูลโดยข้อมูลจะถูกห่อหุ้มด้วย Header ในแต่ละชั้น

ส่วนประกอบสำคัญของ TCP Headers
- Port (Source/Destination) : ช่องทางเข้า-ออกของข้อมูล
- Sequence/Acknowledgement Number : เลขลำดับ เพื่อใช้ในการประกอบข้อมูลให้ถูกต้องตามลำดับ
- Checksum : ใช้ตรวจสอบว่าข้อมูลเสียหายระหว่างทางหรือไม่
- Flag : คำสั่งพิเศษที่บอกว่า Packet นี้จะต้องจัดการยังไง (SYN,ACK,FIN)

กระบวนการ Three-way Handshake (การเริ่มเชื่อมต่อ)
ใช้ในการตกลงเลขลำดับเริ่มต้น (ISN) ระหว่าง 2 เครื่อง
1. SYN :  Client ส่งคำขอเริ่มต้นเชื่อมต่อ
2. SYN/ACK  : server ตอบรับและส่งคำขอเริ่มต้นกลับไป
3. ACK : ยืนยันพร้อมเริ่มการส่งข้อมูล

การปิดการเชื่อมต่อ (Closing Connection)
เมื่อข้อมูลส่งเสร็จแล้ว จะมีการปิดระบบเพื่อคืนทรัพยากรให้กับระบบ
1. FIN : ฝั่งหนึ่งแจ้งว่า "ส่งเสร็จแล้ว ขอคำการปิดการเชื่อมต่อ"
2. ACK/FIN : อีกฝั่งตอบกลับ "รับทราบ และขอปิดฝั่งฉันด้วย"
3. ACK : ฝั่งแรกยืนยัน และปิดการเชื่อมต่อ

#### UDP/IP
UDP (User Datagram Protocol)
UDP ต่างจาก TCP อย่างสิ้นเชิง 
UDP เป็น stateless ไม่มีการทำ Three-way Handshake 
- จุดเด่น : เร็วมาก
- การใช้งาน : เหมาะกับงานที่ยอมให้ข้อมูลหายไปได้บ้าง เช่น Video Streaming

ข้อดีและข้อเสียของ UDP
ข้อดี
- ความเร็วที่สูงมาก : เพราะไม่ต้องรอการตอบกลับ ส่งอย่างเดียว
- ประหยัดทรัพยากร : ไม่ต้องจองคิวและรักษาการเชื่อมต่อเหมือน TCP
- ยืดหยุ่นสูง : ให้ software เป็นคนควบคุมความเร็วในการส่ง
ข้อเสีย
- ไม่รับประกันข้อมูล : ส่งไปแล้ว ไม่รู้ข้อมูลถึงไหม มีการศูนย์หายไหม ข้อมูลผิดเพี้ยนรึป่าว
- ไม่เสถียร :  ถ้าเน็ตไม่ดี User จะพบกับการกระตุกไรงี้
- ไม่มีระบบตรวจสอบ 

โครงสร้าง Header ของ UDP
มีความซับซ้อนน้อยกว่า TCP มาก เพื่อลดภาระ
- Source/Destination Port : ระบุ Port ต้นทางแบบสุ่ม และ Port ปลายทางแบบเจาะจง
- Source/Destination IP : ระบุที่อยู่ IP ผู้ส่งและผู้รับ
- TTL (Time To Live) : กำหนดอายุของ Packet ไม่ให้วิ่งจนอุดตัดใน Network
- Data : ข้อมูล

#### Port 101 
เข้าใจเรื่อง Port : ท่าเรือ
ให้ ท่าเรือ เป็นตัวแทนของ Port และ ให้ เรือแต่ละประเภทจะต้องจอดท่าเรือของมัน ถ้าไม่ตรงกันก็จอดไม่ได้ 

พอร์ตในคอมพิวเตอร์ คือ ค่าตัวเลขตั้งแต่ 0-65535

Common Ports 
คือ พอร์ตมาตรฐานที่กำหนดมาว่า แอปพลิเคชั่นควรใช้ Port อะไร 

| Protocol | Port | Description                                                    |
| -------- | ---- | -------------------------------------------------------------- |
| FTP      | 21   | ใช้สำหรับส่งไฟล์ระหว่าง Client และ server                      |
| SSH      | 22   | ใช้ Remote คอม ผ่าน Command line แบบปลอดภัย                    |
| HTTP     | 80   | ใช้สำหรับส่งข้อมูลเว็บไซต์ www ทั่วไป (World Wide Web)         |
| HTTPS    | 443  | เหมือน HTTP แต่มีการเข้ารหัสข้อมูล                             |
| SMB      | 445  | ใช้แชร์ไฟล์และอุปกรณ์ต่างๆ เช่น เครื่องพิมพ์ (Printer) ในวงแลน |
| RDP      | 3389 | ใช้ Remote เข้าไปใช้งานหน้าจอ Desktop ของเครื่องอื่นแบบเห็นภาพ |
