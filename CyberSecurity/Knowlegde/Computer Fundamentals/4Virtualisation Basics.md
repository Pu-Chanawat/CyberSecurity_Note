#### Introduction
**Virtualization** : เปลี่ยนคอมหนึ่งเครื่อง ให้กลายเป็นหลายเครื่อง

**เป้าหมายของการเรียน**
- ทำความเข้าใจว่าการรันแอปบน Server แบบแยกเครื่องทำไมถึงไม่มีประสิทธิภาพ
- เรียนรู้การทำ Virtualization 
- เข้าใจส่วนประกอบ เช่น Virtual Machine (VM)
- เรียนรู้ว่า container เข้ามาช่วยรีดประสิทธิภาพ hardware ให้ดียิ่งขึ้นได้อย่างไร

#### Virtualization Overview
**ยุคก่อนแนวคิด Virtualization**
" 1 เครื่อง = 1 แอปพลิเคชัน"
เมื่อก่อน การรัน Application เขาจะรัน 1:1 กันเลยซึ่งมีข้อเสียคือ
1. ต้นทุนสูง 
   เพราะถ้าต้องการรัน Application อื่น ก็ต้องซื้อเครื่องเพิ่ม
2. การใช้งานต่ำ 
   คือการรัน Application ต่อ 1 เครื่อง เนี้ยมันใช้งานเครื่องได้ไม่เต็มที คือใช้งานจริงแค่ 20 - 30 % ทำให้เสียของที่ไม่ได้ใช้แบบเปล่าประโยชน์
3. การติดตั้ง
   เพราะการติดตั้งแต่ละเครื่องต้องใช้เวลา

**การมาของ Virtualization**
Virtualization ได้มาการเสนอแนวคิดว่า " จะเป็นยังไง ถ้าเราสามารถรัน application ได้หลายอันในเครื่องเดียวอย่างปลอดภัย " 
Virtualization ได้นำสิ่งที่เรียกว่า Hypervisor (คนจัดสรรทรัพยากร) มาใช้งาน
ลองนึกภาพว่า คุณมีคอมอยู่เครื่องนึง แล้วต้องการแบ่งให้เพื่อน 3 คนใช้ คนหนึ่งใช้ window คนสองใช้ Kali  คนสามใช้ ubuntu แต่ปัญหาคือเรามีคอมพิวเตอร์แค่เครื่องเดียว Hypervisor เลยเข้ามาช่วยในการแก้ปัญหาเรื่องนี้ โดยมันจะทำงานเป็นคนจัดสรรทรัพยากร ดังนี้
1. แบ่งทรัพยากร : คือการแบ่งว่า window เอา ram ไปเท่านี้นะ cpu ไปเท่านี้ Kali เอา ramเท่านี้ cpuเท่านี้ เป็นต้น
2. สร้างกำแพงกั้น : VM แต่ละเครื่องจะเข้าใจว่าตัวเองเป็นเครื่องจริงเพียงเครื่องเดียวนะ ถ้าเกิดมีการติดไวรัสก็จะไม่ลามไปเครื่องอื่นและเครื่องจริง
#### Virtualization Components
- Hypervisor : คือตัวจัดการทรัพยากร แบ่งออกเป็น 2 ประเภท 
  1. type 1 คือรันบนเครื่องเปล่า แรงแต่ติดตั้งยาก
  2. type 2 คือรันบนระบบปฏิบัติการ เช่น window มันสะดวก
- VM (Virtual Machine) : จำลองคอมทั้งเครื่อง มี OS ram,cpu เป็นของตัวเอง ปลอดภัยเพราะแยกเป็นส่วนชัดเจน
- Container : จำลองสภาพแวดล้อมที่แอปต้องใช้ โดยแชร์ Kernel กับเครื่องจริง ทำให้เบาเครื่องและไวมาก
- จุดต่าง : VM เน้นปลอดภัยและรัน OS ที่ต่างกันได้ ส่วน Container เน้นความเบาและไว
